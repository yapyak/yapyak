---
title: YAP0054
name: Currency unsupported
severity: warning
summary: `Intl.NumberFormat` does not know the code, so the runtime falls back
---


A `currency` style names a code the platform cannot format.

{% diagnostics %}
```ts
t('Price: {amount, number, currency BTC}', { amount });  // warning: not ISO 4217
t('Price: {amount, number, currency EUR}', { amount });  // ok
```
{% /diagnostics %}

The check runs against `Intl.supportedValuesOf('currency')`, the same list the `isCurrency` guard uses. See [Numbers](/guide/formatting/numbers) for the `Currency` type that mirrors it.

The code is a warning rather than an error, because the runtime handles it: it formats the number for the locale and appends the code, so `{amount, number, currency BTC}` renders as `1,234.50 BTC` and reports [YAP0035](/reference/diagnostics/YAP0035) once. Codes the standard does not carry, such as those used for crypto, keep working.

A typo like `EURO` or `eur` reports the same way, so read the code before dismissing the warning. `format.number` takes any code without a compile-time check, because its currency can be a runtime value.
